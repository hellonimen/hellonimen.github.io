Final Year Project BSc (Hons) Cybersecurity · APU × De Montfort

Following a payload across the layer boundary.

Most scanners find isolated bugs. This project builds a deliberately vulnerable AI chatbot and a black-box scanner that proves an LLM-layer weakness can causally drive a web-layer exploit, tracing one payload end to end.

Author Ong Pei Chun (Marcus) · Asia Pacific University · 2026
The two programs

One sound tool assessing one unsound target.

The repository holds two independent programs that talk only over HTTP. The contrast is the point.

The target

DVAI

Deliberately Vulnerable AI app

A minimal Flask customer-support chatbot, insecure by design. It is the smallest app that can host all six target vulnerabilities, in the spirit of DVWA and OWASP Juice Shop. Lab use only, never deployed.

The tool

AVSA

Automated Vulnerability Scanner & Assessor

A clean, modular Python scanner. It treats DVAI as a remote black box, starts from one ordinary user account, discovers routes itself, and detects every finding the way a real external attacker would reproduce it.

Attack surface

Six vulnerabilities, two layers.

Three classic web flaws and three flaws specific to LLM-integrated apps, each mapped to its OWASP category.

SQL InjectionA03:2021 · InjectionLogin form, unparameterised query

The contribution

Two cross-layer attack chains.

AVSA does not just list six findings. It captures a shared evidence artifact that links two findings into a single chain, proving the LLM flaw drove the web exploit.

Chain 1 — Active delivery

LLM → WEB · primary contribution
LLMPrompt Injection
→
LLMInsecure Output Handling
→
WebStored XSS
→
WebIDOR delivery

An injected instruction makes the bot emit a malicious response. The output crosses the boundary: it is stored raw, then served through the IDOR hole, firing as XSS in a victim's session.

Chain 2 — Recon-driven

LLM → WEB
LLMSystem Prompt Leakage
→
ReconSchema & routes spilled
→
WebSQL Injection
→
WebIDOR

Leaking the hidden prompt spills internal detail: table and column names and the private chat route. That recon parameterises the web-layer probes the scanner was never handed up front.

Methodology

  • BuildStand up DVAI and plant the six vulnerabilities, each left exploitable on purpose.
  • BreakAVSA attacks black-box over HTTP, detects each flaw and reconstructs both chains.
  • DefendA hardened build and the written analysis show what correct mitigation looks like.

Run as Scrum sprints. Scanner stance: authenticated black-box, one foothold account, no route list or schema given.

Stack

Python Flask SQLite Jinja2 vanilla JS OpenAI gpt-4.1-mini requests

React was deliberately rejected: its auto-escaping would neutralise the Stored XSS the project needs to demonstrate. AVSA itself is built to clean, tested, modular standards.
